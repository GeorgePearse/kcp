How to interpret this

Deadline success uses all offered messages as the denominator. Duplicate arrivals never earn extra delivery credit. Late arrivals beyond the fixed observation window are excluded from delivery credit. Raw records preserve all arrivals. Latency percentiles include only delivered messages, pooled across repeats. Missing messages did not arrive within the bounded observation window; this does not prove permanent loss. TX bytes are combined endpoint interface counters after connection setup, including retransmissions, ACKs and link headers; these are not physical-wire bandwidth measurements.

KCP variants: nodelay=1, interval=10ms, fastresend=2, windows=128, MTU=1200. “kcp” enables built-in congestion control; “kcp_nocc” disables it. Candidate settings are listed in provenance. Plain UDP has no retransmission or ordering guarantee and is a reference, not a reliable replacement. ENet: one reliable ordered channel, MTU=1200, default reliability/congestion settings. TCP: CUBIC, TCP_NODELAY, fixed 256-byte message framing. Encryption is absent for all variants. Every process uses a 1ms service loop. Offloads TSO/GSO/GRO are disabled on all test interfaces.

Profiles apply independently on both router egress interfaces. Delay values are per direction, so 50ms gives approximately 100ms RTT before queueing. At the standard workload, the 128kbit/s profile is deliberately below the 204.8kbit/s application load. Burst loss uses a two-state Gilbert–Elliott model. The outage drops packets for approximately two seconds, starting two seconds after GO; exact transitions are recorded per run. Random trials are unseeded; repeat parameters are reproducible, packet loss sequences are not. No real Wi-Fi or cellular traces are used.
